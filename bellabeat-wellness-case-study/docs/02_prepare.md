# 2. Prepare

## Data source & location

[FitBit Fitness Tracker Data](https://www.kaggle.com/datasets/arashnic/fitbit) (Kaggle, CC0
Public Domain, made available via Mobius) — generated by respondents to a distributed survey via
Amazon Mechanical Turk. Downloaded with `kagglehub.dataset_download("arashnic/fitbit")` (see
[data/raw/README.md](../data/raw/README.md)).

The archive ships as two date-range folders, each a set of daily/hourly/minute/second-level CSVs:

- `data/raw/2016-03-12_to_2016-04-11/` (32 days)
- `data/raw/2016-04-12_to_2016-05-12/` (31 days, 1 day overlap with the first period on Apr 12)

## Organization

Long-format CSVs, one row per user × timestamp, at several granularities (daily activity, hourly
steps/calories/intensity, minute-level steps/calories/intensity/sleep/METs, second-level heart
rate, and daily weight log). Key table used for the core analysis: `dailyActivity_merged.csv`
(15 columns: steps, distance, active-minutes breakdown by intensity, calories, per user per day).

## Credibility check — ROCCC

| Criterion | Assessment |
|---|---|
| **Reliable** | Small, self-selected sample (Amazon Mechanical Turk respondents) — see limitations below |
| **Original** | Third-party (Mobius/Kaggle), not first-party Bellabeat or FitBit data — see note below |
| **Comprehensive** | Covers steps, distance, activity intensity, calories, sleep, heart rate, weight — but optional data types have far fewer participants (see below) |
| **Current** | **Not current** — collected in 2016; smart-device usage patterns and device capabilities have likely shifted materially since |
| **Cited** | Public domain, clearly licensed and documented on Kaggle |

**This dataset does not fully ROCCC**, and the case study itself flags this — it is explicitly a
proxy dataset, not Bellabeat's own data. The most important limitations found during this
inspection:

1. **Small, inconsistent sample size.** `dailyActivity_merged.csv` has **35 unique users** in the
   first period and **33** in the second (33 users appear in both, 35 in total across periods) —
   well short of a robust sample, and short of the "thirty" quoted in the case study text.
2. **Gender is unknown.** Bellabeat's products are marketed specifically to women, but this
   dataset records no demographic information at all — this is the single biggest limitation for
   directly transferring findings to Bellabeat's customer base, and is called out explicitly in
   the Act-phase recommendations.
3. **Very uneven data completeness.** Optional/harder-to-log data types have far fewer
   participants than daily activity: `sleepDay_merged.csv` has only **24** unique users (3
   duplicate rows), `weightLogInfo_merged.csv` only **8** users (and the `Fat` column is null in
   65 of 67 rows — almost unusable), and `heartrate_seconds_merged.csv` only **14** users. Any
   sleep/weight/heart-rate finding in this analysis applies to a much smaller, likely
   non-representative subset of the sample.
4. **The two time periods are not equally complete.** Users average **~13 logged days** in the
   first period (Mar 12–Apr 12) vs. **~28.5 logged days** in the second (Apr 12–May 12) — the
   first period looks like a partial/ramp-up window. The Process phase will treat the second
   period as the primary window for daily-level analysis and document this decision.
5. **77 of 940 rows (8.2%)** in the second period have `TotalSteps == 0` for a full day — likely
   a tracker not worn rather than a genuine zero-activity day; flagged for the Process phase.

## Licensing, privacy, security, accessibility

- CC0 Public Domain — no restrictions on use.
- Fully anonymized: users are represented only by a numeric `Id`, no names, no demographic or
  location data beyond what's listed above.
- Kept locally in `data/raw/` and `data/processed/`, both excluded from Git via `.gitignore`
  (large, and the source is public/reproducible — see `data/raw/README.md`).

## Issues to resolve in Process
